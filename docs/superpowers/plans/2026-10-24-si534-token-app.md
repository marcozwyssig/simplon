# si#534 `token: app` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A leaf that declares `token: app` and binds `repository: <owner>/<repo>` gets, in every generated workflow, a GitHub App token scoped to that one repository, as `GH_APP_TOKEN` in its step env.

**Architecture:**
- The loader accepts a second issuer value.
- workflowgen gains one function that turns such a leaf into a derived token step plus an env entry.
- `_render_job` calls it for every `command:` step. That covers both the derived release job and product jobs, because both are rendered there.

**Tech Stack:** Python 3.12, pydantic (loader), pytest.

**Spec:** `docs/superpowers/specs/2026-10-18-si449-homebrew-tap-design.md`, section B and the second amendment of 2026-10-24.

## Global Constraints

- The action is pinned `actions/create-github-app-token@bcd2ba49218906704ab6c1aa796996da409d3eb1` with the comment `# v3.2.0`. Measured on 2026-10-24: that SHA is the v3.2.0 tag.
- The inputs, exactly:
  - `client-id: ${{ secrets.<PREFIX>_CLIENT_ID }}`;
  - `private-key: ${{ secrets.<PREFIX>_APP_KEY }}`;
  - `owner: <owner>`;
  - `repositories: <repo>`;
  - `permission-contents: write`.
  - `app-id` is deprecated at v3.2.0 (measured) and is never written.
- `<PREFIX>` is the repository's name (the part after `/`), upper-cased, with `-` written as `_`. So `marcozwyssig/homebrew-tap` gives `HOMEBREW_TAP`.
- The leaf's step env gets `GH_APP_TOKEN: ${{ steps.<id>.outputs.token }}`. No secret or token ever appears in a `run:` line.
- `token:` accepts `github`, `app` or absent. Any other value stays a DIAGNOSIS.
- Every new `raise` gets a census entry in `src/tests/test_refusal_census.py`.
- Suite: `deploy/orchestrator/.venv/bin/python -m pytest`. Three `test_tasks_docs` failures are root-bound and pre-existing.
- No em dash in anything written.

## Review Focus

- **An aggregate `command:` step in a product job whose plan contains a `token: app` leaf.** One `run:` line would carry the token to every leaf. Expected: a render-time diagnosis that says to run the leaf as its own step. Pinned in Task 2.
- **A `token: app` step under `if: ${{ !inputs.dry_run }}`.** The derived token step must carry the same `if:`, so a dry run mints no token and needs no secret. Pinned in Task 2.
- **`repository` bound as `homebrew-tap`, without an owner, or as `a/b/c`.** Expected: a diagnosis naming the form `<owner>/<repo>`. Pinned in Task 2.
- **A step that already declares `GH_APP_TOKEN` in its own `env:`.** Silently overwriting it would hide which value wins. Expected: a diagnosis. Pinned in Task 2.
- **Two `token: app` steps in one job.** Each needs its own step `id:`. Two equal ids are invalid YAML for GitHub. Pinned in Task 2.
