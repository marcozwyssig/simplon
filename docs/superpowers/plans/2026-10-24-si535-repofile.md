# si#535 adapters.repofile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One adapter commits one file to a branch of another GitHub repository. It answers in three distinct outcomes, and it reads its own write back.

**Architecture:**
- `adapters/github.py` already builds a non-lazy PyGithub client for the product's own repository and maps every failure to `Unanswered`. It gains a sibling that does the same for a named repository and a given token.
- `adapters/repofile.py` builds on that sibling with the contents API.

**Tech Stack:** Python 3.12, PyGithub 2.x, pytest, and the real-HTTP stand-in `src/tests/githubstandin.py`.

**Spec:** `docs/superpowers/specs/2026-10-18-si449-homebrew-tap-design.md`, section C.

## Global Constraints

- Three outcomes, never two:
  - `written` carries the new commit's sha;
  - `already current` means the file is byte-identical, and nothing is committed;
  - `refused` carries the API's status and message (`github.said`).
- "Already current" must never read as a failed push, nor a failed push as current.
- Read back: after a write, the file at the new commit equals the content. If it does not, the outcome is `refused`, with the reason "read back differs".
- Nothing manager-specific lives in the adapter: no "formula" and no "brew" in it. A later Scoop bucket reuses it.
- Tests use the real-HTTP stand-in, never a mock of PyGithub. See the stand-in's docstring for why.
- Suite: `deploy/orchestrator/.venv/bin/python -m pytest`.

## Review Focus

- **The branch does not exist in the target repository.** Expected: `refused` with GitHub's 404 or 422 text, never `written` to the default branch. Pinned in Task 2.
- **An empty token.** Expected: `refused` before any request, naming the missing token. The body in si#536 refuses an empty `GH_APP_TOKEN` by name too, but the adapter must not send an anonymous request. Pinned in Task 2.
- **The file exists but is a directory, or the path names a directory.** The contents API returns a list. Expected: `refused`, never a crash. Pinned in Task 2.
- **Content that differs only in a trailing newline.** It is not "current". Expected: `written`. Pinned in Task 2.
- **The update races, and the PUT answers 409 because the sha moved.** Expected: `refused` with the 409, and no retry. Pinned in Task 2.

**Interfaces:**
- Consumes: `github.other(name, token)`, `github.said(exc)` and `github.Unanswered` (Task 1).
- Produces:
  - `class State(Enum)`: `WRITTEN = "written"`, `CURRENT = "already current"`, `REFUSED = "refused"`;
  - `@dataclass(frozen=True) class Outcome`: `state: State`, `commit: str = ""` (set only for WRITTEN), `reason: str = ""` (set only for REFUSED);
  - `write(repository: str, branch: str, path: str, content: bytes, message: str, token: str) -> Outcome`. It never raises for a GitHub or network failure: those are REFUSED.

- [ ] **Step 1: Extend the stand-in.** The state gains `"files": {(branch, path): bytes}` and `"branches": {"main"}`. Add these routes:
  - `GET /repos/o/n/contents/<path>?ref=<branch-or-sha>`: 404 for a missing file or branch. Otherwise the file with base64 `content`, `sha` and `type: file`. A path that is a prefix of stored paths answers a JSON list, like a directory.
  - `PUT /repos/o/n/contents/<path>`: body `{message, content, sha?, branch}`. 404 for an unknown branch. 409 when `sha` does not match the stored blob. Otherwise store, and answer `{"commit": {"sha": <new>}, "content": {...}}`. `GET ...?ref=<that commit sha>` must answer the stored content.
  - `state["corrupt_readback"]`: a GET by commit sha answers different bytes.
