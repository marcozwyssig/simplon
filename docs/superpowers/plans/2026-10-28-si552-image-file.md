# si#552 `build:image-file` and `test:file` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The kernel takes one file per platform out of a built or published image and checks it in a libc-free container, leaving a verdict record si#553 can bind.

**Architecture:**
- Two catalogue tasks modelled in firn (`tasks.firn`) and generated by `./simplon.sh build model`.
- Their bodies live in a new module `src/simplon/tasks/imagefile.py`. It reuses `tasks/image.py`'s helpers (`_declared_for`, `read_built`, `platform_reference`, `index_manifests`, `_emulation_advice`, `provenance`) and does not copy them.
- The kind `file` gains an optional `platform:` field.
- `{tag}` expansion is one helper in `image.py`, used by `smoke` and by `test:file`.

**Tech Stack:** Python 3.12+, docker CLI, oras 1.3.4 (pinned host binary), firn model + `build model`, pytest.

**Spec:** `docs/superpowers/specs/2026-10-28-si552-image-file-design.md`

## Global Constraints

- **The kind:** `file` gains `field f_platform { key = "platform"; shape = "text" }` in `src/firn/model/simplon/vocabulary/kinds.firn`. It holds one platform, for example `linux/arm64`.
- **The coordinates:** `build:image-file` and `test:file`.
- **The test image:** `FILE_TEST_IMAGE = docker.pinned_image("busybox:1.37.0-musl@sha256:5cec3fc171c87218698e85a52af7087de727372aae264a787b8112901a5b0092", "simplon.tasks.imagefile")`. The index digest was measured on 2026-10-28 with `docker pull`.
- **The test run line:** `docker run --rm -i --platform <p> --network none <lifecycle flags> -v <abs file>:/run/file:ro FILE_TEST_IMAGE /run/file <shlex.split(argv)...>`.
- **`timeout`** on `test:file` is required, an int number of seconds greater than 0. A run past it is red: `"no answer within <n> s"`, and its container is removed with `docker rm -f <name>`.
- **The record** of `test:file` is `{"file": <entry>, "verdict": N, "runs": [{"reference": <entry path, product-relative>, "id": "sha256:<hex>", "platform", "argv", "expected_rc", "rc", "verdict"}]}`. The old record is deleted first, and the record is written even when the run is red.
- **`{tag}`** is replaced by a literal `str.replace`. No other placeholder exists.
- **The Python param for the path inside the image is `inside`.** The spec's `from` is a Python keyword. This is a ruling; the spec's text means the same param.
- **Generated files are never hand-edited.** Run `./simplon.sh build model` (or `support workflows` where named), then `git add -A`, then `./simplon.sh test generated`.
- **Every new refusal** gets a census entry when `test_refusal_census.py` asks for one. Each one is a diagnosis.
- **Suite:** `/root/git/simplon/deploy/orchestrator/.venv/bin/python -m pytest` from the worktree root. Do not set `PYTHONPATH`, because `test_wheel.py` reads it.
- **Writing rules:**
  - No em dash (U+2014) in anything written.
  - Commits carry Marco's identity via the `GIT_*` env vars.
  - Messages go through a heredoc.

## Review Focus

1. **A file entry whose `platform:` is not among the image's `platforms:`.** Expected: refused before docker is asked, naming both lists. Pinned in Task 2.
2. **`inside` names a directory or a symlink to nothing.** Expected: refused with the path. Nothing is left at the entry's `path:`, and no stopped container is left behind. Pinned in Task 2, in the e2e test of Task 5.
3. **A test file that hangs (reads stdin forever).** Expected: red after `timeout`, the container is gone (`docker ps -a --filter name=<name>` is empty), and a record with a non-zero verdict exists. Pinned in Task 4's e2e test.
4. **A file the host cannot run (foreign platform, no binfmt).** Expected: red, and the message carries `_emulation_advice`. It is not a bare "exited 126". Pinned in Task 4 with a recorded docker result.
5. **A re-run after the file changed.** Expected: the new record's `id` is the new sha256, so a release bound to the old record cannot pass the new bytes as tested. Pinned in Task 4.
