# si#487 `release:check` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A kernel task `release:check <tag>` that refuses a dispatch release before anything is cut, held as the first member of every release aggregate a `workflows: release:` names, lifted in front of the cut by the generator; simplon's own `release-version` goes.

**Architecture:** The body `check(tag: str) -> int` sits in `simplon/tasks/release.py` beside `tag`, over `gitops` (one new helper, `tags_at`). The load rule lives in `manifest/ports.py` beside rule 8 and gets the `workflows:` release names from `load.py`, which already holds the raw data. `workflowgen._release` emits the first leaf before the cut/stamp shell when its task is `release:check`.

**Tech Stack:** Python 3.12, git CLI, firn model (`./simplon.sh build model`), pytest.

**Spec:** `docs/superpowers/specs/2026-11-03-si487-release-check-design.md`

## Global Constraints

- Pattern, fixed, no manifest key: `^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$` (use `fullmatch`).
- Checks run in the spec's table order; the first red one returns 1 at once.
- No GitHub API call, no `token:`, no `publishes:` on `release:check`. It is offered, not placed.
- `GITHUB_REF` unset: from-main is skipped with a log line, never red, never silent.
- The fetch is the existing `gitops.fetch_branches()`; any failure is red. `release:tag`'s warning at `tasks/release.py:75` stays.
- Local tags are not consulted for "taken"; only `gitops.remote_tag_commit` (tri-state: sha / `""` / `None`).
- English in code, messages and docs; no em dash (U+2014) anywhere.
- Commits: `GIT_AUTHOR_NAME="Marco Zwyssig" GIT_AUTHOR_EMAIL=marco@zwyssig.info GIT_COMMITTER_NAME="Marco Zwyssig" GIT_COMMITTER_EMAIL=marco@zwyssig.info git commit -F -` with a quoted heredoc, ending with the two trailer lines `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01UJTdTwXkTwG5ezBqD82YfG`. Messages `feat(si#487): ...` / `docs(si#487): ...`.
- Every task ends green on: its own test files via `cd src && ../deploy/orchestrator/.venv/bin/python -m pytest <files> -q`, `./simplon.sh test typecheck-python`, `git add -A && ./simplon.sh test generated` (it compares against the INDEX: stage first), and `cd src && ../deploy/orchestrator/.venv/bin/python -m pytest tests/test_refusal_census.py -q`.
- Three `tests/test_tasks_docs.py` failures are root-bound and pre-existing on this machine; a fourth failure is real.

## Review Focus

1. A hostile or padded version (`v1.0.0; touch pwned`, `" v1.0.0"`, `v1.0.0\n`): refused by the pattern, nothing run, the value quoted in the message (`!r`). Test in Task 1.
2. A dispatch started on a tag (`GITHUB_REF=refs/tags/v1.0.0`) or a PR ref: red from main, naming the ref. Test in Task 1.
3. A checkout with no `origin` remote: red at the fetch with the fetch message, not a traceback and not "off main". Test in Task 1.
4. HEAD already carries `tag` itself (re-run) plus a non-version tag (`iol-17.18.02`): green. Test in Task 1.
5. A repository whose default branch is not `main` (`master`): `GITHUB_REF=refs/heads/master` passes, `refs/heads/main` (absent) is red. Test in Task 1.
