# si#522: simplon's firn M2 ships, and the kernel validates a fresh export against it - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A product with only the simplon wheel (or image) runs `test manifest-model` and `firn validate` judges its fresh manifest export against the M2 the kernel ships.

**Architecture:** The four M2 packages move into `src/simplon/m2/` and ship as package data. A new catalogue task `test:manifest-model` exports the manifest, stages a throwaway firn project below the output root (export + the installed M2 as a path dependency), and runs `firn validate` there through `toolchain.invocation`. `support toolchain firn` scaffolds it; simplon places it on itself.

**Tech Stack:** Python 3.11+, setuptools package-data, `importlib.resources`, firn v0.2.0 image, pytest.

**Spec:** `docs/superpowers/specs/2026-10-24-si522-firn-m2-design.md`

## Global Constraints

- The contract packages are exactly `manifest`, `pipeline`, `catalogue`, `vocabulary`; `architecture` and `components` never ship.
- The wheel's top level stays `simplon` plus its `.dist-info` (`test_the_wheel_installs_nothing_beside_simplon`).
- One source: no second copy of a `.firn` file in the tree.
- The product's own `firn.toml` is never read or written by the new task.
- firn's rc passes through unchanged: 0 clean, 1 model wrong, 2 usage, 3 no project, 70 firn's own fault. A manifest that does not load or export is rc 1 with the reason.
- No kernel default image pin: the task takes `image` from `with:`.
- No em dash (U+2014) anywhere. Commits with the env identity and the trailers in CLAUDE.md memory.
- Python via `deploy/orchestrator/.venv/bin/python`; suite `./simplon.sh --no-tui test suite`; `git add -A` before `./simplon.sh --no-tui test generated`; regenerated files are committed with the change that caused them.

## Review Focus

1. A product with `build_root:` set: the container starts in mount/build_root/cwd, so the check project's `cwd` must be relative to `<root>/<build_root>`; a check dir outside it is rc 1 with the reason, not a firn rc 3. (Task 3, `test_a_check_dir_outside_the_build_root_is_refused`.)
2. A check dir left from an earlier run (another product name, a stale export) must not leak into this run's verdict: the stage is rebuilt from empty every time. (Task 3, `test_a_leftover_file_does_not_survive_staging`.)
3. An installed simplon whose package lacks the M2 (a broken wheel) is rc 1 naming the missing directory, not firn's E200. (Task 3, `test_a_package_without_the_m2_is_refused_by_name`.)
4. A product that keeps a `firn.toml` at its root (netctl's own model): byte-identical after the run, and firn starts in the stage, not at the nearest `firn.toml` above. (Task 3, `test_the_products_own_firn_toml_is_untouched`.)
5. A re-run of `support toolchain firn` in a product that already has `test model`/`build model` adds `test manifest-model` and keeps the other two. (Task 4, `test_a_second_scaffold_adds_only_the_manifest_check`.)
