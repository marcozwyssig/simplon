# si#568 firn tasks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The kernel runs everything a firn product does with its own model. `build:model` loses two second sources and passes firn's rc first. `test:model` and `test:model-format` are new. The product binary is built and used through `build:model-binary` and `binary:`. The scaffold writes these coordinates instead of `toolchain:run`.

**Architecture:**
- Every firn run goes through `toolchain.invocation` + `docker.run_container`, as `build:model` does today (`tasks/firngen.py:30-40`).
- One code table and one naming function live in `firngen.py` and serve every firn task.
- `docker_argv`/`invocation` gain a kernel-internal `entrypoint` keyword. The manifest cannot set it.
- The scaffold's `firn` profile switches to task entries, the way its `manifest-model` entry already is. A new `firn-binary` profile carries the binary commands.

**Tech Stack:** Python 3.12, pytest, docker, firn images (`ghcr.io/marcozwyssig/firn:v0.2.0` in the suite), firn model generation (`./simplon.sh build model`).

**Spec:** `docs/superpowers/specs/2026-11-04-si568-firn-tasks-design.md`

## Global Constraints

- firn's rc is passed through unchanged. A code that is the kernel's own verdict is 4 for W300/W301 and 1 for "no file" and "a reported file is missing", and its line says the verdict is the kernel's.
- firn's codes as of v0.5.0 `ExitCode.java`: 0 OK, 1 MODEL_ERROR, 2 USAGE, 3 IO, 4 OUTPUT_NOT_CURRENT, 5 RESOURCE_EXHAUSTED, 6 DUPLICATE_REGISTRY_KEY, 70 INTERNAL. Docker's own 125, 126 and 127 are named as docker's. Any other code is red and named as unknown.
- `build:model` keeps W300/W301 (now rc 4), 0644, "no file" and "reported file missing". It drops the id-line-only refusal and the DELETED refusal. When the output is not JSON and rc != 0, it returns firn's rc.
- `binary:` is relative to `cwd`, runs with `--entrypoint` set to it, and is refused at run time when missing, naming `build:model-binary`.
- `build:model-binary`:
  - the product root is mounted at its own host path, and that path is the workdir;
  - it runs as the caller, with `network: none`;
  - `GRADLE_USER_HOME=<cwd>/.gradle`;
  - argv `gradle --offline firnBinary`, then a smoke run `build/firn/firn --version`.
- No `bootstrap:` parameter anywhere.
- No em dash (U+2014). Artefacts in English. Every new assertion is seen red first.
- Commits: env identity `Marco Zwyssig <marco@zwyssig.info>`, quoted heredoc, trailers `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01UJTdTwXkTwG5ezBqD82YfG`.
- Test commands:
  - single files: `cd src && ../deploy/orchestrator/.venv/bin/python -m pytest <files> -q`;
  - gates: `./simplon.sh test typecheck-python`, `git add -A && ./simplon.sh test generated`, `./simplon.sh test release-notes`;
  - full: `./simplon.sh test suite`.

## Review Focus

1. **A firn run that prints a usage text on rc 2, or the registry refusal on rc 6.** Expected: rc 2 or 6 comes back with firn's text. It is never 1 and never "not its JSON report" alone.
2. **`binary:` naming a file that exists but is not executable, or is a directory.** Expected: docker's 126 or 127 is named as docker's ("not executable / not found"), not as an unknown firn code.
3. **`test:model` over a project with nothing to validate** (an empty `firn.toml` project). Expected: firn's own rc and text. The kernel does not invent green or red here (decision 2: no second verdict).
4. **`build:model-binary` run twice.** Expected: the second run finds `<cwd>/.gradle` and works offline. No root-owned files are left in the tree (`--user`).
5. **A product scaffolded before si#568 runs `support toolchain firn` again.** Expected: its existing `build model`/`test model` `toolchain:run` lines are untouched (never clobber), and only `test model-format` is added.
