# si#859: catalogue task `test:unit` - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A catalogue task `test:unit` runs a product's own pytest suite (one or more roots) in a kernel-provisioned venv, red on an empty collection, so cleon-firn, cleon, asbundle, netctl and biz-cockpit's orchestrator need no hand-written pytest step.

**Architecture:** The task is a firn instance in `src/firn/model/simplon/catalogue/tasks.firn`; `./simplon.sh build model` generates `src/simplon/catalogue.yaml` and the task class `src/simplon/tasks/test_unit.py` with a protected region pointing at the body. The body lives in a new module `src/simplon/tasks/unittests.py` and reuses `src/simplon/adapters/pyvenv.py` (`ensure_venv`, and the pip install `venv_python_pip` does for `test:gate`).

**Tech Stack:** Python 3.12, pytest, the launcher's venv mechanism.

**Spec:** `docs/superpowers/specs/2026-11-22-derived-workflows-design.md` section 5.6 (D7). Ticket si#859 with its comments (measurement and Marco's decisions, 2026-11-25).

## Global Constraints

- Everything generated goes through firn: the task is modelled in `tasks.firn`, never added to `catalogue.yaml` or a generated class by hand; `./simplon.sh build model` then `./simplon.sh test generated` green.
- Parameters, decided (Marco, 2026-11-25): `paths` (a list of directories, one pytest run), `requirements` (path to a requirements file), `config` (optional, path to a pytest configuration, passed as `-c`). All paths relative to the product root.
- pytest is installed only if the requirements did not bring it, with one log line saying so (Marco).
- An empty collection (pytest exit 5) is red and names the paths.
- Out of scope (Marco): uv/pyproject projects (biz-cockpit's backend) and unittest suites (firn).
- New refusals: a census entry of the right kind in `src/tests/test_refusal_census.py` if they are load-time; run-time refusals are `context.TaskRefused` with the way out (not `ValueError`, see #891).
- No em dash (U+2014); no counts typed into prose; English. Suite: `deploy/orchestrator/.venv/bin/python -m pytest -q --no-header -p no:cacheprovider <paths>` (no `-n`).

## Review Focus

- A requirements file that fails to install (a typo in a pin): red, quoting pip, never a run of pytest against a half-built venv.
- A second run after the requirements file changed: the venv reflects the new file, not the first one (a cached venv keyed on nothing would keep stale packages: the recurring defect).
- A path in `paths` that does not exist: refused before pytest runs, naming it (pytest would otherwise exit 4 or 5 and the message would blame the collection).
- pytest present in the requirements at a pinned version: that version is what runs (no second install).
- Tests that import the product's own sources through `conftest.py` `sys.path` inserts (cleon, asbundle, cleon-firn): rootdir and cwd are the product root, so those inserts resolve.
