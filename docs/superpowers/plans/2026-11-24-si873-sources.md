# si#873: product sources - a private submodule checked out at its pinned commit with a token - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A product declares `sources: [{ submodule: <path>, secret: <NAME> }]`, and every job of every workflow `support github workflows` writes checks that submodule out at its pinned commit right after the checkout, through a kernel command `support sources` that reads the token through the si#833 secrets module.

**Architecture:** A new top-level manifest section `sources:`, read by `simplon.manifest.sources`. A new catalogue task `support:sources` (body `simplon.tasks.sources`), placed in the kernel's `support` tree, runs `git submodule update --init --recursive <path>` per source with the token handed to git through `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n` (never argv) and `GIT_CONFIG_GLOBAL=/dev/null` (a stale global rewrite cannot win). `workflowgen.render` inserts the step after the checkout of every job that has one; a derived (`prepared`) job carries it as its first preparation step with an id the leaves' conditions read.

**Tech Stack:** Python 3.12+, pydantic, firn model + templates (`./simplon.sh build model`), git, pytest, mypy.

**Spec:** `docs/superpowers/specs/2026-11-22-derived-workflows-design.md` section 5.5 (the `sources:` bullet, D9), as narrowed by #873's body (Marco, 2026-11-23) and the decisions below.

## Decisions this plan carries

Marco, #873 body (2026-11-23):
1. Only the submodule form: `sources: [{ submodule: lib/platform, secret: PLATFORM_REPO_TOKEN }]`. `{repo, path, ref?, secret?}` reopens when a product needs a foreign repository in CI.
2. The submodule is checked out **at its pinned commit**, with the token passed per invocation; stale global `url.*.insteadOf` must not win (netctl's measured cause: git prefers the first equal-length match).
3. `secret` goes through the si#833 secrets module: masked, checked before the run.

Marco, 2026-11-24, choice list in this session:
4. **A kernel command, not a verbatim step.** Catalogue task `support:sources`, run in a job as `./<product>.sh support sources` (si#8: every step a command a developer can type). It also runs locally.

Measured 2026-11-24 (git 2.47.3, local fixture: a superproject whose `.gitmodules` URL is `https://github.com/x/platform.git`, rewritten to a local bare repo):
- The rewrite handed through `GIT_CONFIG_COUNT=…`/`GIT_CONFIG_KEY_0=url.<target>.insteadOf`/`GIT_CONFIG_VALUE_0=https://github.com/x/` checks the submodule out **at the pinned commit** (`HEAD~1` of the submodule repo, not its tip).
- With a stale global `url.<wrong>.insteadOf https://github.com/x/` present, the env rewrite **loses** and the clone fails: netctl's cause reproduced, for env config as for `-c`.
- With `GIT_CONFIG_GLOBAL=/dev/null` added, the same call succeeds. So the kernel hides the global config for this one call instead of deleting the user's global sections (netctl's `lab.yml` deletes them, which on a developer machine would destroy their own config).
- `netctl.sh` names `lib/platform` only in a comment: the launcher does not need the submodule to run, so `support sources` can run before it exists.
- Not measured: a nested private submodule (`--recursive` below a private one) inheriting the env rewrite; a Windows or macOS cell.

My calls (the executor posts them on #873 in Task 0; Marco may overrule):
- **Token outside Actions.** When the secret's variable is unset or empty: under `GITHUB_ACTIONS=true` it is refused (diagnosis naming the secret, and that a fork or Dependabot pull request gets no secrets); outside Actions the submodule is updated with the user's own git configuration and credentials, and the run says so in one line. A token that is set is used in both places.
- **`GIT_CONFIG_GLOBAL=/dev/null` only on a call that carries a token.** Without one the user's configuration (credential helpers, ssh rewrites) is what makes the clone work.
- **`secret:` is optional.** A public submodule needs none; its call is a plain `submodule update`.
- **Run-time diagnoses** (each with a census entry if the census reaches it; otherwise named in `READS_INLINE` with the reason, as the census requires):
  - the path is not a submodule in `.gitmodules` (names the submodules it has);
  - a `secret:` is given and the submodule's URL does not start with `https://github.com/` (the rewrite would not apply and the token would silently go unused);
  - git exits non-zero (its output, redacted, and the path).
- **Load-time diagnoses** in `simplon.manifest.sources`: `sources:` not a list; an entry not a mapping; an unknown key (lists `submodule, secret`); `submodule:` not a non-empty relative path, or containing `..`; `secret:` not `[A-Za-z_][A-Za-z0-9_]*`; two entries with one path.
- **Placement in a job:** right after the checkout (and `setup-python` where present), before the docker probe, the disk preflight and `support install`. In a derived job it is preparation step `prepare_sources`, and every later leaf waits for its success like the others. A job with `checkout: false` (the si#861 decide job, a declared job that writes its own checkout) gets none.
- **Step env:** `<SECRET>: ${{ secrets.<SECRET> }}` for every source with a secret, on that step only.
- **A product with no `sources:`** gets no step, and every rendered file stays byte-identical.

## Review Focus

1. **A stale global `url.*.insteadOf` on the machine.** Expected: ignored on a call with a token (the Task 2 test builds it in a temporary `HOME`, sees the call fail without `GIT_CONFIG_GLOBAL=/dev/null` and succeed with it).
2. **The token on a command line.** Expected: never; a test asserts that no argv the task hands to `run` contains the token, and that `secrets.read` registered it (so `redact` masks it in git's error output).
3. **The secret is empty under Actions** (fork pull request, unset repository secret). Expected: refused before git runs, naming the secret; never an unauthenticated clone that fails three lines later with "repository not found".
4. **A derived job whose sources step fails.** Expected: no leaf after it runs (`steps.prepare_sources.outcome == 'success'` in every later leaf's condition; the first leaf runs on GitHub's default `success()`).
5. **A product with `sources:` and a job with `checkout: false`.** Expected: that job gets no sources step and no `secrets.` reference.
