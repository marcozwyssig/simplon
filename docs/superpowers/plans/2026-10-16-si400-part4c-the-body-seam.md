# si#400 part 4c: a command runs its task's class, and `impl:` leaves the catalogue - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every command's body runs through a `Task` class. A catalogue coordinate uses its generated class,
imported lazily. A product task uses a class the kernel builds from its `impl:`. `catalogue.yaml` names no
`impl:` any more: the body lives in the class's protected region, and the model's `body` seeds it.

**Architecture:** This is spec step 3, cut down by Marco's choice list of 2026-10-16 (si#400 comment
6214912886): the body seam only. `CommandSpec` keeps every other field, and the `Command` classes are plan 4d.
`PORTS` stays generated from the model, and `signatures.py` stays and reads `cls().run`. The one runtime
path is `task.body_of(spec)`. `CommandSpec.impl` stays a `module:attribute` reference: for a catalogue
coordinate it names the generated class (`simplon.tasks.build_image:BuildImage`), for a product task its
function. The class is what runs either way.

**Tech Stack:** Python 3, pytest, mypy. firn v0.1.0 only through `./simplon.sh build model`.

**Spec:** `docs/superpowers/specs/2026-10-15-part-4-tasks-as-generated-classes-design.md`, with si#400 comment 6214912886.

- **A Python class name from an instance name**: firn's `className` (4b) is `toFirstUpper` plus `_x` → `X`

  Both agree on every catalogue name, which the 4b class-name test already holds through `_class_of`.

## Review Focus

1. **A body that is no `Task` and no function** (a typo'd reference, a module constant). `body_of` must
   say which command and what it found, never run it. Pinned in Task 1.
2. **Two product commands on one `impl:` with different `with:`/`params:`.** Each needs its own class (a
   class per task name, not per impl, as si#420 decided for the export). Pinned in Task 1.
3. **A product CLI generated by `tasks:generate`** must call the class's `run` for a catalogue coordinate.
   A generated `module.Class(...)` call would construct the class and run nothing, with rc 0. That is the
   house defect, in generated code. Pinned in Task 3.
4. **`catalogue.yaml` that still writes `impl:` on a task** (an old hand edit, or a product copying the
   form). It is a second source of a body, so it is refused as a diagnosis with a census entry. Pinned in Task 3.
5. **Startup stays lazy**: `simplon --help` imports no more task modules than before. Pinned in Task 2.

```python
def class_name(name: str) -> str:
    """A task class's name from its instance name: the Tasks template's `className`, in Python (snake_case
    to PascalCase over `[a-z0-9_]`, which is all `mangle` writes)."""
    return "".join(part[:1].upper() + part[1:] for part in name.split("_"))


def class_ref(coordinate: str) -> str:
    """The generated class of a catalogue coordinate, as a `module:attribute` reference (si#400 4c). The
    class module is imported only when this is resolved, so naming every coordinate costs nothing."""
    from simplon.domain.manifestmodel import mangle
    name = mangle(coordinate)
    return f"simplon.tasks.{name}:{class_name(name)}"


@functools.lru_cache(maxsize=None)
def task_class(ref: str, key: str, *, where: str) -> type[Task]:
    """The Task class `ref` names: a generated class as it is, or - for a product task, until spec step 6
    generates its class - one built here around the function, keyed by the task's own name (si#420: two
    tasks on one function are two classes). Anything else is refused, naming the command."""
    from simplon.domain.manifest import resolve_ref
    target = resolve_ref(ref, where)
    if isinstance(target, type) and issubclass(target, Task):
        return target
    if inspect.isfunction(target) or inspect.isbuiltin(target):
        return type(class_name(key.replace("-", "_").replace(":", "_")) or "ProductTask", (Task,),
                    {"KEY": key, "run": staticmethod(target), "__module__": target.__module__})
    raise ValueError(f"{where}: `{ref}` is {type(target).__name__} {target!r:.60}, neither a Task class nor a "
                     f"function, so there is no body to run")


def body_of(spec: "CommandSpec", *, where: str) -> Callable[..., object]:
    """The callable a leaf runs: its task class's `run`. The one runtime path (si#400 4c)."""
    return task_class(spec.impl, spec.task or where, where=where)().run
```

  Add `import functools`, `import inspect`, `from collections.abc import Callable`, and under
  `TYPE_CHECKING`, `from simplon.domain.manifest import CommandSpec`. The imports inside the functions keep
  `domain.task` free of an import cycle with `manifest`. Check with `test_architecture` that the layers
  allow it. If they do not, rule and ledger.
