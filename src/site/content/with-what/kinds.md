## Ports

A catalogue task takes and gives artifacts through its ports. A port accepts a kind and every kind that
refines it; a port that binds a parameter receives the bound artifact's name in it.

A command binds a port with `produces: { <port>: <artifact> }` on an output and
`consumes: { <port>: <artifact> }` on an input. The artifact is an `artifacts:` entry whose kind the port accepts.
A port that binds a parameter hands the artifact's name to it; `with: { name: ... }` on that parameter is read as
the same binding, and `simplon manifest migrate` rewrites it into the port's.

**A release consumes the results of the tests on what it publishes.** Every publish leaf has an `evidence` input
port accepting `test-result`. A command under `ci: release:` that consumes an artifact must bind
every test result about it there, and at least one must exist (rule 6). A test result is about what its producer consumes, directly:
a unit test of the source is not a test of the image built from it. The notes, the tag, the bundle and the evidence
itself need none.

The evidence is read before anything is published (si#434). The load checks the binding; at run time every bound
record is read before the publish body runs, and a record that is missing, red or without a verdict stops it.
`release:image` also compares what the record tested with what it would push (si#439): each run names the
reference and the daemon id it tested, so an image never tested under that tag, or rebuilt since, is refused.
